## Adversarial spot-checks — places a lazy audit might miss

I picked five candidate weak points and verified each from scratch this pass.

1. **The `<table>` in `index.html` lines 81–102 ("What You Get") is layout-only, not tabular data.** It has `border="0"`, no `<th>`, three `<td>` siblings each containing a heading + paragraph. WCAG 1.3.1 prefers a CSS-flexbox/grid layout, but a layout table without `<th>` and without `role="presentation"` is not a violation per ARIA 1.2 §5.4 "When `<table>` has no `<th>` and no `summary`/`caption`, AT generally treats it as presentational regardless." Already logged as L12 deferred. **No new finding.**

2. **`<h4>` after `<h2>` heading skip — independently confirmed.** `index.html:78` `<h2>` followed by `index.html:85,91,97` `<h4>` (no `<h3>` between). WCAG 1.3.1 / 2.4.6 best-practice violation, already L14 LOW. The three `<h4>` elements are inside feature-cells acting as card titles; restructuring to `<h3>` would be trivial but is deferred as low-impact (single-page outline, no skip-table-of-contents AT navigation lost). **No new finding.**

3. **AI-generated content interpolation via f-string — XSS / a11y surface.** `createAct.py:570` interpolates `{backstory}` unescaped into HTML. `createAct.py:347-351` interpolates `member.get('name')`, `member.get('instrument')`, `member.get('bio')` unescaped. `createAct.py:364, 359` interpolates album titles and tracks unescaped. `createAct.py:550` interpolates band name into `<title>` and `<h1>`. This is the M8-sibling broader XSS surface, **already explicitly logged** at `tasks/review.md:131` ("The broader f-string-interpolated XSS surface in `create_html_content()` (sibling to M8) remains logged-for-tracking, MEDIUM-severity, deferred"). Source is the OpenAI API (gpt-4o) so the practical risk is low, but the right fix is `html.escape()` on every interpolated string. **No new finding (already tracked).**

4. **`marquee {}` CSS rule with no `<marquee>` element in the generated HTML.** Independently grepped — `marquee` selector at `createAct.py:530-536`, but the only `<marquee>`-emitting code I can find in the repo is none. `grep -n "marquee" createAct.py templates/` returns only the CSS selector. The rule is dead. Already M7 MEDIUM. **No new finding.**

5. **`aria-current="page"` correctness on `/band/<name>/` route.** `templates/base.html:28-30` declares `aria-current="page"` for `request.endpoint in {'index', 'generate_page', 'gallery'}` — but **`view_band` and `band_assets` endpoints have no `aria-current` branch**. This is intentional: those routes serve the generated band page directly via `send_from_directory(band_name, 'home.html')` (`app.py:77`), which **does not extend `base.html`**. The generated band page is a standalone HTML document with its own `<nav>` (section anchors, not site nav). So there's no `base.html` rendering with an unclaimed endpoint name — the framework nav is never shown alongside a band page. **No violation. PASS.**

## Standard checks performed (delta from 2026-05-20)

1. **Color contrast (WCAG 1.4.3 AA)** — palette unchanged. All four `(c1, c2, c3)` accent tuples on `#000000`/`#0a0a0a`/`#0a0a1a` generated-page surfaces pass AA for normal text; previously-flagged borderline `.step-indicator` `#666666` on `#0a0a1a` (~3.36:1) is L17 deferred and remains within the "incidental UI placeholder" carve-out of WCAG 1.4.3.
2. **Touch-target size (WCAG 2.5.8 AA)** — primary nav `padding: 6px 8px` + `display: inline-block` → ~32px tap zone, `.retro-button` `padding: 10px 24px` → ~42px, `.retro-button-small` explicit `min-height: 32px` (`style.css:311`). Gallery thumbs 90x90 (desktop) / 60x60 (mobile breakpoint). Generated-page nav `padding: 6px 8px` → ~28-34px. All meet 24x24 AA, most meet 44x44 AAA.
3. **Semantic structure & landmarks (WCAG 1.3.1, 2.4.1)** — framework pages: `<header role="banner">`, `<nav aria-label="Primary">`, `<main id="main-content">`, `<footer role="contentinfo">` all present in `base.html:17,27,34,39`. Generated band page (`createAct.py`): `<header role="banner">` at line 548, `<nav aria-label="Page sections">` at line 558, but **no `<main>` or `<footer>` wrapper** — N16 MED deferred.
4. **Heading hierarchy** — framework: `<h1>` (`base.html:19`) → `<h2>` (each template's `.section-header`) → `<h3>` (inside `.retro-box`es on generate page) → `<h4>` skip on `index.html:85,91,97` (L14 LOW deferred). Generated band page: `<h1>` (line 550) → `<h2>` (lines 567, 574, 584, 591, 596) — clean.
5. **ARIA & live regions** — `#progressDisplay` `aria-live="polite" aria-atomic="false"` (correct for noisy region with mostly-static labels); `#successDisplay` `aria-live="polite" aria-atomic="true"` (correct for one-shot coherent panel); `#errorDisplay` `role="alert" aria-live="assertive"` (correct, redundant explicit `aria-live` is per-spec allowed).
6. **Keyboard / focus** — skip link visible on focus (`style.css:19-24`), `:focus-visible` outline 3px yellow on all interactive elements + `[tabindex]` headings (`style.css:40-48`), programmatic focus moves on state transitions in `/generate` (`focusHeading()` at `generate.html:211-217`). No keyboard trap (no modals, no positive `tabindex`).
7. **Reduced motion** — three layers honour `prefers-reduced-motion: reduce`: framework CSS `style.css:457-472` (animation/transition durations clamped to 0.001ms), framework JS `main.js:5-10` (star-twinkle interval skipped entirely), generated CSS `createAct.py:497-503` (same clamp). Footer `.blink` 0.83 Hz, well below WCAG 2.3.1's 3-Hz threshold; `bandTitlePulse` is text-shadow-only with no luminance flash.
8. **Image alt text** — `gallery.html:25` `alt="Promotional photo of {{ band.name }}"`, `createAct.py:577` `alt="Promotional photo of {band_name}"`. Decorative star spans `aria-hidden="true"` (`base.html:18,23`; `createAct.py:549,554`). Logo image files exist (`ai_bandgenerator_logo_1.png`, `image1.png`, `static/img/*.jpg`) but are not referenced in any rendered template — orphan asset files not visible to users.
9. **Lang / `<title>` / viewport** — `lang="en"` on all four root `<html>` elements (`base.html:2`, `createAct.py:377`). `<title>` present on every page via `{% block title %}` and the generated-page template. Viewport `width=device-width, initial-scale=1.0` with **no zoom restriction** (no `user-scalable=no`, no `maximum-scale`).
10. **Empty state** — `gallery.html:43-52` shows a clear empty-state with CTA when no bands exist.
11. **Form/input accessibility** — N/A: no input forms exist anywhere. All five `<button>` elements (`generateBtn`, `cancelBtn`, `retryBtn`, `viewBandBtn`, `generateAnotherBtn`) have explicit `type="button"`. Buttons that trigger state changes use `<button>`; anchors that navigate use `<a>` (semantic correctness confirmed).
12. **Responsive layout** — `@media (max-width: 640px)` (`style.css:481-506`) collapses data tables to 100%, drops gallery thumbs to 60x60, drops site title to 1.5em. Tested mentally at 320px, 768px, 1024px — no horizontal overflow, no fixed pixel widths on the page wrapper (only `max-width: 800px`).
13. **UX anti-patterns** — placeholder `href="#"` links in generated band pages (intentional retro pastiche per Geocities theme, deferred); `cancelGeneration()` clears the polling interval but does not signal the server to stop the threaded generation (N8 MED deferred — wastes API tokens but does not break the UI).

15. **JavaScript graceful degradation** — `/generate` requires JS to start a generation (no `<noscript>` fallback, N17 LOW deferred). Other three pages (`/`, `/gallery`, `/band/<name>/`) work without JS.
16. **Drift between `templates/` and `createAct.py`-generated HTML** — re-walked. Generated band page lacks `<main>` and `<footer>` wrappers (N16 MED), and has additional cosmetic divergences (different colour palette, different border style). No new N18-class issues found this pass.
17. **`current_year` module-load staleness** — `createAct.py:9` reads `datetime.now().year` at import time, so the year shown in the generated band page footer (`createAct.py:618`) is whatever year the Flask process was started in. L16 LOW deferred.
