Independent spot-checks this pass not appearing in prior logs:

1. **Gallery sort order** (`app.py:53-67`) — `glob.glob("*/home.html")` returns directories in OS readdir order (typically insertion order on ext4, but not lexicographic). UX: gallery is small enough that ordering doesn't yet manifest as a usability issue. WCAG impact: none (no SC requires deterministic listing order). Not raising as a finding; would be a Low-severity UX polish to add `sorted(...)` if/when the gallery grows past ~20 bands.
2. **`display_name` derivation** (`app.py:60`) — `re.sub(r'([A-Z])', r' \1', band_name).strip()` converts `MoonlitReverie` → `Moonlit Reverie`. Edge case: a band-name starting with a lowercase letter (or all-lowercase) would render with no leading space (correct), and consecutive caps like `MTV` would become `M T V` (potential UX nit — would render an acronym as letters). Generated band names from `createAct.py` are sanitised to camel-cased alphanumerics, so consecutive caps are vanishingly unlikely in practice. **Not a finding.**
3. **Gallery `<a>` to `view_band` route** (`gallery.html:31, 36`) — passes `band.directory` (raw directory name) as `band_name`. Confirmed `SAFE_BAND_NAME = ^[A-Za-z0-9_\-]+$` (`app.py:21`) gate-keeps both `view_band` and `band_assets`. Any directory matching `*/home.html` but not the regex would 404, which is the correct fail-safe. **Not a finding.**
4. **HTML parse validation** — `python3 html.parser.HTMLParser` over all four framework templates: zero errors. (Reported in Phase 3 below.)
5. **Skip-link target** — `base.html:12` → `#main-content`; `base.html:34` `<main id="main-content" tabindex="-1">` present. Skip-link is the first focusable element (verified by reading base.html linearly). **PASS.**
6. **`aria-current="page"` injection on each nav link** — `base.html:28-30` uses Jinja `{% if request.endpoint == ... %}` conditional. Independent re-check: all three endpoint names (`index`, `generate_page`, `gallery`) match the route function names in `app.py:42, 48, 54`. **PASS.**
7. **`tabindex="-1"` on three section headings** (`generate.html:35, 90, 111`) plus `<main id="main-content" tabindex="-1">` (`base.html:34`) — all four programmatic focus targets present and not duplicated. CSS `main:focus, h3[tabindex]:focus { outline: none; }` (`style.css:53-56`) is scoped to non-keyboard focus only; `:focus-visible` still applies (`style.css:40-48`). **PASS.**
8. **`role="alert"` + `aria-live="assertive"` on error display** (`generate.html:109`) — correct pattern per ARIA APG for time-critical error messaging. Inner heading `tabindex="-1"` (`generate.html:111`) receives programmatic focus via `focusHeading('errorTitle')` (`generate.html:240-247`). Triple-redundant signalling (role+aria-live+focus) is appropriate for error severity. **No finding.**
9. **CSS focus indicator contrast** — `:focus-visible { outline: 3px solid #ffff00; }` (`style.css:46`) — 3px width exceeds WCAG 2.4.11 (AA, focus appearance) 2px minimum requirement; yellow `#ffff00` clears WCAG 1.4.11 3:1 against all backgrounds in use (`#000022`, `#0a0a1a`, `#0a0a2a`, `#1a0a0a`, `#333366`). **PASS.**
