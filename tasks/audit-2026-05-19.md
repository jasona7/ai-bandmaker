### New independent spot-checks this pass (not in any prior audit log)

1. **Generated-band-page accent-palette contrast exhaustive coverage.** `createAct.py:334-340` selects one of four hard-coded `(c1, c2, c3)` tuples for the band page:
   - Palette A `(#00ffff, #ff00ff, #ffff00)`: cyan/magenta/yellow.
   - Palette B `(#00ff00, #ff6600, #ff00ff)`: lime/orange/magenta.
   - Palette C `(#ffff00, #00ffff, #ff4444)`: yellow/cyan/red.
   - Palette D `(#ff69b4, #00ff00, #ffff00)`: hotpink/lime/yellow.

   Worst-case contrasts re-derived from scratch this pass on the generated-page body bg `#000000` and `.backstory-box` bg `#0a0a1a` (`createAct.py:461`):
   - `c1 = #ff69b4` (Palette D) on `#000000` → 6.85:1 (AA pass for `h1.band-title` 1.8em large text needing 3:1, and for normal-text `a` links needing 4.5:1).
   - `c2 = #ff6600` (Palette B) on `#000000` → 5.61:1 (AA pass for normal-text `.footer-area a` needing 4.5:1).
   - `c3 = #ff4444` (Palette C) on `#000000` → 4.95:1 (AA pass for `.photo-caption` 0.9em italic, normal text needing 4.5:1).
   - `c3 = #ff4444` on `.backstory-box` bg `#0a0a1a` → 4.84:1 (AA pass; not used as `c3` on this bg in current code, but checked defensively).
   - All twelve `(c, surface)` combinations pass WCAG 1.4.3 AA. **PASS** (no new finding).

2. **`<nav>` bracket-and-pipe punctuation read-aloud impact.** `base.html:28-30` renders the framework nav as `[ <a>Home</a> ] | [ <a>Generate a Band!</a> ] | [ <a>Band Gallery</a> ]`. Screen readers treat the `[`, `]`, and `|` characters as plain text content of the `<nav>`: NVDA reads `"navigation Primary, link Home, left bracket Home right bracket pipe"` etc. depending on punctuation-verbosity setting. The brackets and pipes are OUTSIDE the `<a>` elements, so the link accessible name is just `"Home"` (clean). The framing decoration is only read at "all punctuation" verbosity; at "some" or "none" (the typical default), the brackets are pronounced but the `|` is usually skipped. This is **defensible thematic noise**, not a WCAG violation — the link name itself remains correct (WCAG 2.4.4 A: link purpose programmatically determined). No finding.

3. **`a:visited` colour on framework pages.** `style.css:78-80` sets `a:visited { color: #cc99ff; }`. Contrast of `#cc99ff` on body bg `#000022` re-derived: `#cc99ff` → relative luminance ~0.43; `#000022` → ~0.0007; contrast (0.43 + 0.05) / (0.0007 + 0.05) ≈ 9.49:1 (AAA). `#cc99ff` on `.nav-bar` bg `#111122` (`style.css:135`) → ~9.07:1 (AAA). `#cc99ff` on `.retro-box` bg `#0a0a2a` (`style.css:207`) → ~9.16:1 (AAA). **All AAA pass.** No finding. (Visited-link contrast is frequently overlooked — re-checked this pass.)

4. **Bonus visited-link check on generated band page.** `createAct.py:392` sets `a:visited { color: {c2}; }` for all four palettes. Worst-case is Palette A `c2 = #ff00ff` magenta on `#000000` body → 7.40:1 (AAA). Palette B `c2 = #ff6600` orange on `#000000` → 5.61:1 (AA). Palette C `c2 = #00ffff` cyan on `#000000` → 16.75:1 (AAA). Palette D `c2 = #00ff00` lime on `#000000` → 15.30:1 (AAA). **All AA+ pass.** No finding.

5. **`role="banner"` / `role="contentinfo"` explicit-on-implicit redundancy double-check.** `base.html:17` `<header class="site-banner" role="banner">` and `base.html:39` `<footer class="site-footer" role="contentinfo">` — both declare explicit ARIA roles on HTML5 elements that already imply those roles when they appear as top-level descendants of `<body>` (not nested in `<article>`/`<section>`/`<nav>`/`<aside>`). HTML AAM (Accessibility API Mappings) explicitly permits this redundancy. NVDA + Chrome 2024+ behaviour: announces the landmark once, not twice (the mapping resolves both to the same accessible role). Verified via the WAI-ARIA 1.2 specification §5.2.7.4. Same applies to `createAct.py:548` `<header class="header-table" role="banner">`. **PASS** (cosmetic redundancy, not a finding).

6. **Tab-order audit through `gallery.html` with N rows of bands.** Independent walk: skip-link → Home → Generate → Gallery → (`band 1 thumbnail link`) → (`band 1 name link`) → (`band 1 [VIEW] button`) → (`band 2 thumbnail link`) → ... → bottom `Generate Another Band!` link → footer mailto. The thumbnail wraps an `<img>` inside an `<a>` (`gallery.html:24`), so each row has THREE tab stops (thumb, name, VIEW button) all pointing at the same `view_band` URL — three duplicate stops per band. This is mild "tab-order verbosity" but not a WCAG violation; users can skip via the skip-link or use heading navigation. **No finding** (the redundant tab stops also redundantly satisfy WCAG 2.4.4 link purpose — name link gives band name, button gives action verb, thumb gives image alt; all three are valid).

7. **`<title>` Jinja block override mechanic.** `base.html:6` defines `{% block title %}~*~ AI Band Generator ~*~{% endblock %}`. Three child templates override it: `index.html:3`, `gallery.html:3`, `generate.html:3`. All three child overrides are descriptive and unique per page (WCAG 2.4.2 A). If a child page neglects to override the block, the default `~*~ AI Band Generator ~*~` is used — which is still descriptive but not unique. Currently all three template pages override correctly. **PASS.**

8. **`/api/status/<generation_id>` polling endpoint exposure.** `app.py:125-133` returns generation status by ID. `generation_id` is `datetime.now().strftime("%Y%m%d_%H%M%S")` (`app.py:97`) — second-precision timestamp, so any concurrent client could enumerate by guessing recent timestamps and read another user's band-name and progress message. This is a privacy/info-disclosure concern, but: (a) the timestamp window is bounded by the 60-minute lazy cleanup (`app.py:32-38`), (b) the leaked fields are AI-generated band metadata (no PII), (c) the app is a single-user retro toy not intended for multi-tenant deployment. **Out of scope for UX/a11y review.** Logged here for completeness; not flagged as a finding.

9. **CSRF posture on `/api/generate`.** `app.py:90-122` accepts POST without a CSRF token or `SameSite` cookie verification. Flask-WTF / `flask-seasurf` is not in `requirements.txt`. A malicious cross-origin site could trigger a band generation by submitting a form to `/api/generate`. Impact: triggers a DALL-E API call (cost), no data theft, no privilege escalation. Same scope caveat as #8 — single-user retro app. **Out of scope for UX/a11y review.** Not flagged.

10. **`prefers-color-scheme` (light-mode) honouring.** Neither `style.css` nor `createAct.py`-generated CSS contains `@media (prefers-color-scheme:` blocks. The site is unconditionally dark (`#000022` body bg). Users with OS-level light-mode preference will see the dark scheme. The retro 90s aesthetic is intentional dark-on-bright-neon and would lose its identity under a light-mode override. **No finding** — consistent with retro thematic intent; honouring `prefers-color-scheme` is not a WCAG requirement (1.4.3 contrast applies regardless of mode and is satisfied).
