## MEDIUM

### M1 — Heading hierarchy skips from h2 to h4
**File:** `templates/index.html` lines 85, 91, 97 (feature-box `<h4>` under the `<h2>` "~ What You Get ~" at line 78).
**Problem:** The document outline goes `h1` (site title, base.html line 19) → `h2` (section headers) → `h4` (feature boxes) with no intervening `h3`. Screen-reader users navigating by heading level hit a broken outline and may assume a heading level (and its content) is missing. This is the only place in the app where a level is skipped; `generate.html` and `gallery.html` use a correct h2 → h3 progression.
**WCAG:** 1.3.1 Info and Relationships (A).
**Fix:** Change the three feature-box headings from `<h4 style="color:#...">` to `<h3 class="feature-heading">`, moving the inline color to a class. No visual change is required — style the new `h3` to match the current h4 size/weight. (`.feature-box h4` at style.css line 265 should become `.feature-box h3`.)

### M2 — Progress `aria-live` region is too broad; screen readers announce cryptic ASCII on every 1.5 s poll
**File:** `templates/generate.html` line 33 (`<div id="progressDisplay" ... aria-live="polite" aria-atomic="false">`) wrapping the ASCII bar (lines 39-42) and the step table (lines 44-77); driven by `updateProgress()` in the inline script (lines 183-209), polled every 1.5 s via `setInterval` (line 158).
**Problem:** Because the entire progress panel is a polite live region and its decorative nodes mutate every poll, assistive tech re-announces each changed node: the fill string (`====`), the empty string (`----`), the percent, and step indicators toggling `...` → `[>]` → `[X]`. The result is noisy, near-meaningless speech ("equals equals equals… dash dash dash… bracket X bracket") instead of a clear status. `aria-atomic="false"` means only changed nodes are read, which makes the ASCII churn worse, not better.
**WCAG:** 4.1.3 Status Messages (AA); 1.3.1 (announcements do not convey the intended meaning).
**Fix:** Mark the decorative nodes `aria-hidden="true"` — the `.ascii-progress` block (lines 39-42) and each `.step-indicator` cell — and route the human-readable status into a single dedicated `sr-only` polite region that announces only message + percent (e.g. "Writing backstory, 35%"). Keep `#progressMessage` visible; let one concise live region carry the spoken update. Remove `aria-live` from the wrapping `#progressDisplay`.

## LOW

### L1 — Pending step indicator has sub-AA contrast (decorative placeholder)
**File:** `static/css/style.css` line 369 (`.step-row .step-indicator { color: #666666; }`) on progress-steps-table bg `#0a0a1a`.
**Problem:** `#666666` on `#0a0a1a` ≈ **3.4:1** (recomputed this run), below the 4.5:1 AA threshold for normal text. Impact is limited: the glyph is only the `...` "pending" placeholder; the adjacent step label is readable `#cccccc`, and active states switch to bright green/yellow.
**WCAG:** 1.4.3 Contrast (Minimum) (AA) — borderline; non-essential text.
**Fix:** Lift the pending color to about `#8a8a99` (≈ 4.7:1) to clear AA without changing the retro feel.

### L2 — Empty ASCII progress dashes fail contrast (decorative)
**File:** `templates/generate.html` line 40 (`<span id="progressBarEmpty" style="color:#333333;">`) on retro-box `#0a0a2a`; reset value also set in JS (line 264).
**Problem:** `#333333` on `#0a0a2a` ≈ **1.5:1** (recomputed this run). This is the unfilled remainder of the bar; the essential progress value is conveyed by the `#ff00ff` percent text (passes) and the `#00ff00` fill, so real impact is minimal.
**WCAG:** 1.4.3 (non-essential decoration).
**Fix:** Raise the empty-segment color to ~`#777777`, or (preferred, and consistent with M2) `aria-hidden` the whole bar and treat it as pure decoration.

### L3 — Repeated "[ VIEW ]" links in the gallery lack a per-band accessible name
**File:** `templates/gallery.html` lines 36-38 (`<a ... class="retro-button-small">[ VIEW ]</a>`, one per band row).
**Problem:** Every gallery row renders a link whose entire accessible name is "[ VIEW ]". A screen-reader user pulling up the links list (or tabbing quickly) hears "VIEW, VIEW, VIEW…" with no way to tell which band each targets. It technically passes 2.4.4 Link Purpose (In Context, A) because the same row contains the band-name link, but it fails the stricter 2.4.9 (Link-Only, AAA) and is a real wayfinding annoyance. There are also two adjacent links to the identical URL per row (band name at line 31 and VIEW at line 36), doubling tab stops.
**WCAG:** 2.4.4 Link Purpose (In Context) (A) — borderline pass; 2.4.9 (AAA) fail.
**Fix:** Add a contextual accessible name, e.g. `aria-label="View {{ band.name }}"` on the VIEW link (keep the visible "[ VIEW ]" text). Optionally collapse the two per-row links into one to reduce redundant tab stops.

### L4 — No CSS custom properties; neon palette repeated as magic hex values
**File:** `static/css/style.css` throughout (e.g. `#00ffff`, `#ff00ff`, `#0a0a2a`, `#0a0a1a`, `#333366`, `#ffff00` each recur many times) plus numerous inline `style="color:#..."` in the templates.
**Problem:** Design-system maintainability, not user-facing. Palette changes require hunting duplicated hex literals across the stylesheet and inline template styles.
**Fix:** Define tokens in `:root` (`--neon-cyan`, `--neon-magenta`, `--panel-bg`, `--panel-bg-alt`, …) and reference them; migrate inline color styles to utility classes over time.

### L5 — Inconsistent button font-family stacks
**File:** `static/css/style.css` line 282 (`.retro-button`: `'Comic Sans MS','Trebuchet MS',cursive,sans-serif`) vs line 312 (`.retro-button-small`: `'Comic Sans MS', cursive`).
**Problem:** Component inconsistency; the small button lacks the same fallback chain, so rendering can diverge where Comic Sans is unavailable.
**Fix:** Share one font stack (a variable per L4) across both button classes.

### L6 — Inline styles scattered across templates reduce consistency
**File:** `templates/index.html` (lines 16, 35-62, 66-70, 81-99), `templates/generate.html` (lines 15-16, 33, 35-41, 79, 88-111), `templates/gallery.html` (lines 22, 30-36).
**Problem:** Repeated inline color/spacing/font-size values make the button/spacing system harder to keep consistent and easy to drift. Not user-harming today.
**Fix:** Promote recurring inline patterns (table-cell number styling, section spacing, heading colors) into classes.

### L7 — Indefinite motion is pausable only via OS `prefers-reduced-motion` (acceptable mitigation — noted for completeness)
**File:** `static/css/style.css` lines 448-472 (`.blink` + reduced-motion block); `static/js/main.js` lines 12-25 (star twinkle `setInterval`).
**Problem:** The footer `.blink` and the JS star twinkle run indefinitely (> 5 s, in parallel with content) with no on-page pause control; the only stop mechanism is the OS reduced-motion preference (correctly honored in both CSS and the JS early-return at main.js lines 6-10). Both animations sit on decorative / `aria-hidden` content, blink frequency (~0.83 Hz) is well under the 3 Hz seizure threshold, and neither wraps essential content — so this is broadly compliant.
**WCAG:** 2.2.2 Pause, Stop, Hide (A) — `prefers-reduced-motion` is a widely accepted mitigation; 2.3.1 Three Flashes (A) passes.
**Fix:** None required. Optional enhancement: an on-page "stop animations" toggle for users who cannot set an OS preference.

## Positive observations (verified, not issues)

- Skip link (`base.html` line 12) is correctly offscreen and reveals on `:focus` with a visible outline (style.css 7-24); target `#main-content` has `tabindex="-1"` for reliable focus.
- Every informative image has meaningful alt text (`gallery.html` line 25, "Promotional photo of {name}"); the no-photo case uses readable text, not an empty image.
- `aria-current="page"` on the active nav item (base.html 28-30); `aria-hidden="true"` on the decorative star rows and banner.
- Dynamic state transitions move focus to the new region heading (`focusHeading()` in generate.html 211-247) — correct focus management, no focus loss into a hidden panel.
- Error state exists with `role="alert"` + assertive live region (generate.html 109-117); appropriate.
- Progress and step status are conveyed by text/symbols (`[X]`/`[>]`/`...`, percent), not by color alone — passes 1.4.1 Use of Color.
- Responsive: `max-width` wrapper, tables reflow to 100% width and feature cells stack (`display:block`) at ≤640px; viewport meta present; thumbnails shrink to 60px; no fixed pixel widths that force horizontal scroll at 320px.
- Touch targets meet WCAG 2.5.8 (24×24 CSS px): `.retro-button` ≈ 38px tall, `.retro-button-small` `min-height:32px`, nav links ≈ 32px tall.
