## NEW Findings (2026-05-09 audit)

| ID | Severity | Item | File:line |
|---|---|---|---|
| **N18** | **HIGH** | `info-table` ("How It Works") uses `<td><strong>X</strong></td>` for the three column headers instead of `<th scope="col">X</th>`. Programmatically the table has no header cells, violating WCAG 1.3.1 (Info and Relationships, Level A). The N3 fix in `8bae07f` corrected the equivalent issue in `gallery.html` and `generate.html` but missed `index.html`. CSS already supports `th` (`style.css:244-245` `.table-header-row td, .table-header-row th`), so the fix is purely markup. | `templates/index.html:30-32` |

### Why HIGH

This is the same severity bucket as N3 (which was classified HIGH and fixed surgically in `8bae07f`). Level A WCAG failures are by definition HIGH minimum in this project's calibration, and this is a true Level A failure: a screen-reader user navigating the table cell-by-cell does not get column-header announcements, and "What Happens" content like "Three full albums with track listings are generated" is read without the user knowing it sits under "What Happens" rather than "Step". The `<strong>` styling fixes the visual but not the programmatic semantics.
