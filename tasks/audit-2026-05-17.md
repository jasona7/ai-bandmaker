### New independent spot-checks this pass (not in any prior audit log)

1. **`aria-atomic` asymmetry across the three live regions on `/generate`.** `#progressDisplay` (`generate.html:33`) uses `aria-live="polite" aria-atomic="false"`; `#successDisplay` (`generate.html:88`) uses `aria-live="polite" aria-atomic="true"`; `#errorDisplay` (`generate.html:109`) uses `role="alert" aria-live="assertive"` (redundant — `role="alert"` implies assertive + atomic=true, but the explicit attribute is harmless). The asymmetry between progress (atomic=false) and success (atomic=true) is **defensible**: progress changes incrementally (poll-driven message updates + step-indicator cell mutations), so atomic=false lets SR announce only the changed subtree; success fires once with a single composite payload, so atomic=true announces the whole region. All three start with `display:none`, so none fire on initial page mount (browsers only announce live regions for content that is added/changed while the region is in the accessibility tree; SR behaviour for `display:none` → `display:block` reveal with seeded content is a longstanding edge — in practice NVDA, JAWS, and VoiceOver all re-announce on subsequent `textContent` changes within the now-visible region, which is what this code does). **PASS** (no new finding; N6, N7, N9 carry-overs remain the established items in this surface).
2. **`viewBand()` directory-name URL safety.** `generate.html:281` uses `window.location.href = '/band/' + encodeURIComponent(currentDirectory) + '/'`. `currentDirectory` comes from `data.directory` (`generate.html:171`), which is populated server-side at `app.py:155` from `create_project_directory(band_profile['Band Name'])`. That function (`createAct.py:642-656`) does `''.join(word.capitalize() for word in band_name.split())` — i.e. strips whitespace and CamelCases, but does NOT strip non-alphanumeric characters. If the AI returned a band name containing `/`, `*`, or non-ASCII characters (e.g. "AC/DC", "Sigur Rós", "*NSYNC"), the directory would contain them; `os.makedirs()` might succeed; the round-trip through the URL would `encodeURIComponent` them and then `SAFE_BAND_NAME` at `app.py:73,85` would reject the percent-encoded path on the way back, returning 404. **This is the same latent issue already characterised in `tasks/review-recheck.md` FINDING 2** ("`**VelvetEchoes`" and "`ChaoDeCorais`" pre-existing orphans), framed as LOW because the model prompts implicitly steer away from such names and the security benefit of the regex outweighs the edge case. No new finding — already-logged latent issue. **PASS for new-finding purposes.**
3. **Skip-link target focus mechanics (`<main id="main-content" tabindex="-1">`).** `base.html:34` declares `<main>` with `tabindex="-1"`, making it programmatically focusable but not keyboard-tab-reachable. The skip-link at `base.html:12` (`<a class="skip-link" href="#main-content">`) navigates to the `:target` fragment; modern Chrome/Firefox/Safari all then move sequential focus to the target element when it has tabindex (per HTML5 fragment-navigation spec, since 2018 in all evergreen browsers). `style.css:53-56` suppresses the mouse-induced outline ring via `main:focus { outline: none; }` while `a:focus-visible, button:focus-visible, [tabindex]:focus-visible` at `style.css:40-48` correctly preserves the yellow outline for keyboard focus (`:focus-visible` heuristics treat fragment navigation as keyboard-equivalent). **PASS.**
4. **`aria-current="page"` scope check on generated-band-view URL.** `base.html:28-30` applies `aria-current="page"` to nav links via `{% if request.endpoint == 'index' %}` (and `'generate_page'`, `'gallery'`). The `view_band` route (`app.py:70`) serves a static file via `send_from_directory` — the generated band page does NOT extend `base.html` and does NOT see the framework nav at all; it has its own internal-anchor nav (`createAct.py:558`, `<nav aria-label="Page sections">`). So the `request.endpoint == 'view_band'` case never needs an `aria-current` because the framework nav isn't rendered on those pages. The four enumerated endpoints (`index`, `generate_page`, `gallery`, and implicitly the post-generation `viewBand()` redirect to `/band/<name>/`) all correctly cover the framework-nav surfaces. **PASS** (no finding; behaviour is correct by design).
